# 演讲者层（Presenter Layer）

可编辑层解决「改」，现场演示层解决「台上怎么放」，这一层解决「你怎么讲」。台下那扇屏只看页面，你这扇屏看备注、下一页、时间和观众屏状态。一个人撑完整场，靠的就是这扇屏。

运行时片段在 `assets/presenter-layer.html`，实跑验证过，零依赖、单文件。它跟另外两层一样，是贴在 `</body>` 前的一段 `<style>` + `<script>`。

## 它解决什么

一句话：把「一个人对着投影仪讲」拆成两扇屏，演讲者屏看备注，台下屏只看页面。

现场真正会用到的东西：

- **备注**：每页一张提词卡，写在演讲者屏右边，本地自动保存。
- **下一页预览**：讲这一页时就知道下一页长什么样，转场不用现想。
- **计时**：总时长、本页时长、本页计划、剩余或超时，超时转红。
- **宫格跳页**：`Esc` 打开全页宫格，点哪页跳哪页，现场被追问也不用一页页翻。
- **激光笔与圈选**：红点、红圈同时画在你这扇屏和观众屏上，坐标归一化，两边分辨率不同也对得上。
- **观众屏黑屏 / 白屏 / 冻结**：临时遮住，或让台下停在原页等你讲完。
- **排练记录**：每页实际用时与计划对比，本地留最近 5 次。

## 用户怎么用

- **进视图**：右下角「演讲模式」按钮，或按 `Shift+P`。按钮低调挂在 `right:16px;bottom:16px`，让开上面两层的工具栏。
- **开观众屏**：进视图时浏览器会弹一扇独立观众窗。把它拖到投影或外接屏，在那扇窗里按 F11 全屏。「检查」面板里那个按钮叫「本屏全屏（观众窗按 F11）」，它全屏的是当前这扇演讲者窗。浏览器规定全屏必须由用户手势触发，脚本没法代劳，观众窗只能自己按 F11。
- **演讲者屏长什么样**：顶栏是观众屏状态、自动翻页、检查、设置、重新打开观众屏、退出。左边上下两格是当前页和下一页，右边是备注编辑区，底部是计时三格加两行控制（首页 / 上一页 / 下一页 / 尾页，开始计时 / 重置计时 / 排练）。
- **备注**：直接改。改的过程中显示「保存中…」，300 毫秒后回到「已保存」。按页存本地，切页不丢，刷新还在。
- **退场**：点「退出」。观众窗收到结束信号，显示「演示已结束」，并尝试自动关闭；浏览器不允许自关时，那层深色遮罩会留着。

## 快捷键

键位只在演讲者视图里生效。deck 页面里本层只认 `Shift+P` 一个。

| 键 | 演讲者视图里做什么 |
|---|---|
| `Shift+P` | 从 deck 进演讲者视图。已经在视图里就不再响应 |
| `←` `→` | 上一页 / 下一页 |
| `PageUp` `PageDown` `↑` `↓` 空格 | 也算翻页，翻页笔常发这几个键 |
| `Home` `End` | 首页 / 尾页 |
| `L` | 激光笔开关 |
| `C` | 圈选工具开关 |
| `X` | 清除本页标记，观众屏一起清 |
| `B` | 观众屏黑屏，再按回正常 |
| `W` | 观众屏白屏，再按回正常 |
| `F` | 冻结观众屏，再按恢复并立刻追平当前页 |
| `A` | 自动翻页开关。全局间隔和本页秒数都没设时，按它先弹设置 |
| `R` | 开始 / 结束排练 |
| `?` | 快捷键面板，`/` 同效 |
| `Esc` | 宫格选页；标注工具开着时先退出工具；对话框开着时先关对话框 |

三处跟别层不一样，别记混：

- **入口是 `Shift+P`**。`P` 已被现场演示层占用为打印，本层不抢。
- **视图里的 `F` 是冻结观众屏**。现场演示层的 `F` 全屏在视图里被本层接管，要用全屏，退出视图再按。
- **焦点在备注框里时，所有键都不传给 deck**，字符照常输入，`Esc` 只让备注框失焦。

## 怎么给新做的 deck 加上

**路线一（推荐）：跑注入器**

```bash
node scripts/inject-presenter.mjs 你的deck.html
```

它做四件事：

- 给每个 `<section class="slide">` 补 `data-slide-id`（缺省 `slide-01` 起顺延，重名自动加后缀）和 `data-title`（取该页第一个 `h1/h2/h3` 的纯文本前 60 字）。
- 页面里没有 `SPEAKER_NOTES` 就插一份骨架，页数与 id 对齐，`purpose` / `talk` / `transition` 留空。
- 把 `assets/presenter-layer.html` 贴在 `</body>` 前。已经装过就整段替换，反复跑不堆叠。
- deck 装了可编辑层，顺手把本层的三个选择器补进它的「下载 HTML」清理名单。

加 `--dry-run` 只看改什么、不写盘。跑完必须人工补备注，骨架里只有 id 和标题。`purpose` 写这一页想让观众记住什么，一句；`talk` 写 3 到 5 条；`transition` 写为什么下一页紧接着出现。

**路线二：手工贴**

把 `assets/presenter-layer.html` 整段贴到 `</body>` 之前，再手写一份 `window.__HE_SPEAKER_NOTES__`。

**位置有硬要求：这段脚本必须排在 deck 自己的翻页脚本之后。** 两个原因。一是它执行时就要读 `window.__heDeck` 钩子，钩子得先生效；二是它一上来就抓 `.slide` 列表，抓不到会静默退出，连入口按钮都不挂（贴在 `<head>` 里就是这个下场：页面没有任何反应，也不报错）。

## 页面可选加的两个钩子

**一、`data-slide-id` 与 `data-title`**

```html
<section class="slide statement" data-slide-id="why-now" data-title="为什么是现在">
```

- `data-slide-id` 用小写 slug，别用页码。备注按 id 存，页面重排不串页。
- 运行时读的是 `dataset.slideId` 和 `dataset.title`。`data-slide-id` 缺失时按 `slide-01` 形式兜底，一重排就串页。
- 备注标题、宫格卡片、顶部分组行都从这两个属性来。

**二、`window.__heDeck`**

本层只读两个成员：`index` 和 `go`。有了它，翻页是真函数调用。没有它，本层派发 `ArrowRight` / `ArrowLeft` 键盘事件让 deck 自己走，能翻，一次要跳多页时得循环派发，慢一拍。

位置放在 deck 自己的 `show()` 定义和首次调用之后、键盘监听之前：

```js
  function show(n){ /* deck 原有的翻页实现 */ }
  show(0);
  window.__heDeck = { get index(){ return i; }, go: show, slides };
```

`slides` 留着给别的扩展用，本层不读。注入器跑完会检查有没有这一行，缺了会在输出里提示。

## 备注数据结构 SPEAKER_NOTES

在 deck 里放一份 `window.__HE_SPEAKER_NOTES__ = SPEAKER_NOTES;`，一条对应一页，`id` 必须等于该页的 `data-slide-id`。顺序建议跟页面一致。

| 字段 | 必填性 | 界面表现 |
|---|---|---|
| `id` | 必填 | 备注按它匹配页面。对不上就整条失配，备注区退回「第 N 页」和 `—` |
| `title` | 必填 | 备注标题与宫格卡片。真缺了会退到 `data-title`，再退到「第 N 页」 |
| `purpose` | 必填 | 「本页目的」。真缺了显示 `—` |
| `talk` | 必填 | 草稿里的「【讲述要点】」，数组逐条成行 |
| `transition` | 必填 | 草稿里的「【转场】」 |
| `section` | 可选 | 顶部的章节行与章节剩余时间。缺失整行隐藏 |
| `minutes` | 可选 | 计时区「计划」与备注区的「建议 X 分钟」。缺失显示 `—`，总计划和预计结束时间一起隐藏 |
| `cue` | 可选 | 草稿里的「【舞台提示】」 |
| `interaction` | 可选 | 草稿里的「【互动】」 |
| `delivery` | 可选 | 草稿里的「【表达提示】」 |
| `advance` | 可选 | 草稿里的「【翻页时机】」 |
| `fallback` | 可选 | 草稿里的「【备用方案】」 |
| `pronunciation` | 可选 | 草稿里的「【读音提醒】」 |
| `autoAdvanceSeconds` | 可选 | 本页自动翻页的停留秒数，优先于全局间隔 |

`cue` 到 `pronunciation` 六个字段，写字符串或字符串数组都行。整页备注片段的顺序也固定为这个次序，没填的段落直接不出现。

**必填与降级是两件事**。运行时对任何字段都容错，缺了就降级显示；`scripts/validate-presenter-mode.mjs` 不认这套，`title`、`purpose`、`talk`、`transition` 为空一律报 error。注入器生成的骨架这四项都是空的，补完再校验。

三条硬规矩：

- **`minutes` 与 `autoAdvanceSeconds` 各管一件事**。前者是讲述计划，只影响计时区的计划与剩余；后者是播放行为，只影响自动翻页。一页计划讲 1 分钟，不等于 60 秒后自动翻页。
- **默认写提词卡，不写逐字稿**。`talk` 3 到 5 条，每条一个意思。`purpose` 一句话说清这页要让观众记住什么。
- **没有的现场信息直接省略字段，不要编**。界面缺什么就显示 `—` 或整行隐藏，它不会替你补一句话。

## 几条关键铁律

- **所有演讲者层的 DOM 挂在 `body` 上**，绝不往 `.slide` 里塞。塞进去会被可编辑层 `restore()` 的整段 `innerHTML` 覆盖抹掉，还会被 `save()` 写进 localStorage，从此一直躺在导出的文件里。
- **覆盖物必须自带 `@media print` 隐藏**。本层入口按钮写在 `@media print{#he-presenter-btn{display:none!important}}` 里。deck 自己的打印清单只认 `.hud,.bar,.brandmark,.hint`，不会替你兜底。
- **键盘走 window 捕获阶段先手**，处理完 `stopImmediatePropagation()`。演讲者视图里吞掉全部翻页键，否则本层 `go()` 翻一次、deck 的 window 冒泡监听再翻一次，一次按键走两页。
- **视图内的点击必须 `stopPropagation()`**。`#he-presenter` 上挂了一个整体拦截，观众屏和预览窗各挂一个。不拦的话，点「下一页」按钮会同时撞上 deck 的「点半屏翻页」，一按退两页。
- **观众屏同步只能证明软件页面状态，不能证明 HDMI 线是通的**。状态胶囊的 tooltip 和演前检查的脚注都写死了这句话。现场仍要目视外接屏。
- **观众窗被浏览器拦截时，视图里必须显示「弹窗被拦截」**，且「重新打开观众屏」始终可点。心跳 2.6 秒没回音就落到「未连接」，不会一直挂着「已同步」骗人。

## 与另外两层的共存

**现场演示层**：`P` 打印、`F` 全屏已被它占用，所以本层用 `Shift+P` 进视图；deck 模式下本层对 `P`、`F` 一律放行，原样交给它。两层都挂键盘监听，但本层在 window 捕获阶段，现场演示层在 document 捕获阶段，window 先跑。演讲者视图里本层吞掉按键之后，现场的 `F`、`P` 都收不到，所以视图里的 `F` 是冻结。入口按钮固定在 `bottom:16px`，那两层的工具栏在 `bottom:56px`，三层不叠。

**可编辑层**：它的「下载 HTML」会剥掉自己的工具栏和 lightbox，但它不知道本层存在。deck 同时装了可编辑层，要在它的 `downloadHTML()` 清理选择器里补上本层的三个 id。

原句在 `references/editable-layer.md:112`（`grep 'he-toolbar,.he-style'` 能找到），6 份 examples 里的内联副本在 `examples/heige-pitch.html:385` 这类位置：

```js
[].slice.call(clone.querySelectorAll('.he-toolbar,.he-style,.lb,.he-showbar')).forEach(function(n){ n.remove(); });
```

改成：

```js
[].slice.call(clone.querySelectorAll('.he-toolbar,.he-style,.lb,.he-showbar,#he-presenter,#he-presenter-btn,#he-presenter-style')).forEach(function(n){ n.remove(); });
```

注入器会自动补这一句，但它只认 `.he-toolbar,.he-style` 这个两选择器的旧写法（6 份 examples 都是这写法）。从 `references/editable-layer.md` 的新片段建的 deck 已经带了 `.lb,.he-showbar`，注入器匹配不到，得手工补。

## 生成后验证

```bash
node scripts/validate-presenter-mode.mjs path/to/deck.html
node scripts/validate-presenter-mode.mjs path/to/deck.html --target-minutes 30
```

第一条查结构：页数、`data-slide-id`、备注与页面的对应。第二条额外核对总计划时长与现场给定的分钟数是否对得上。

浏览器实测清单，逐条点一遍：

- 进视图：按钮进得去，`Shift+P` 也进得去。
- 观众窗：允许弹窗时能开出来；拦掉弹窗后视图显示「弹窗被拦截」，「重新打开观众屏」还能救回来。
- 翻页：前后翻，观众屏页码跟着走，两个预览 iframe 不重载（翻十页仍在同一份文档里）。
- 宫格：`Esc` 打开，点一页直接跳过去，`Esc` 或「返回预览」回来。
- 首尾：「首页」「上一页」在第一页置灰，「下一页」在尾页置灰；尾页的下一页预览显示「演示结束」，「尾页」按钮变成「重新开始」，点了回第一页。
- 备注：改完显示「已保存」，刷新还在，切到别的页再切回来内容不串。
- 计时：开始、暂停、继续、重置，四个状态都对。
- 排练：录一轮，结束后弹出排练记录表，含每页实际用时与计划差。
- 自动翻页：开起来能自己走，切到宫格或开始圈选时应暂停，回来从原剩余时间接着走。
- 激光、圈选、清除：三种标注在观众屏上都能看见，`X` 清干净。
- 黑屏、白屏、冻结：`B`、`W`、`F` 各自生效并能恢复，冻结时翻页观众屏不动，恢复后立刻追平。
- 观众窗：手动关掉那扇窗，状态落到「未连接」；点「重新打开观众屏」，恢复到「已同步」并停在当前页。
- 退出：点「退出」，观众窗关闭或显示「演示已结束」。

## 能力边界

- 纯本地、零依赖、不需要账号，打开 HTML 就能用。
- 三条同步通道是 `BroadcastChannel`、`postMessage`、`localStorage`，都只在同一个浏览器、同一个源里有效。跨设备投屏靠的是拖动窗口和 HDMI，本层不负责。
- 不含实时字幕、AI 排练评分、扫码投票、手机遥控。排练记录只做数据汇总，不给评价。
